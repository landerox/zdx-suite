# AGENTS.md — System Instructions for AI Assistants

> **Target Audience:** Claude Code, Codex CLI, Antigravity CLI, OpenCode, Copilot CLI, etc.

This document serves as the root system instruction for any AI agent interacting with this repository. You must read and follow the constraints below before modifying any files.

## 🛠️ Core AI Operational Mandates

When executing a task or generating code, adhere strictly to the following parameters:

1. **Zsh Exclusivity:** Write Zsh-first. Do not use Bash-isms or attempt to write POSIX-sh compliant code if a native Zsh feature is cleaner. Rely on `local` and arrays. The installer implementation is Zsh; `scripts/install.sh` is a minimal Bash 3.2 compatibility launcher only. Keep installation orchestration in `scripts/install.zsh`; `scripts/install_fs.py` is the narrow Python 3.8+ filesystem helper for validation and atomic no-clobber publication. BATS remains a Bash test harness.
2. **Naming Conventions:** Use `kebab-case` for public commands. Private helpers must stay namespaced with their suite-specific prefix (e.g., `_zdx_*`, `_git_*`, `_vpn_*`, `_sys_*`, `_file_*`, `_env_*`, `_py_*`, `_dev_*`, `_ws_*`).
3. **Data vs. UI Streams:** Function `stdout` is strictly for data. All UI messages, warnings, or prompts must go to `stderr`. Use existing suite-specific logging helpers (`_..._info`, `_..._error`, `_..._warn`, `_..._success`). Plans, step progress, results, summaries, and captured tool output follow [`docs/output-spec.md`](docs/output-spec.md) through the core output services; never claim `updated` without before/after evidence, and never hand-roll `(s)` plurals or durations.
4. **Safety & Security:** Never hardcode credentials. Destructive commands (e.g., deletions, cleanups) MUST preview the exact target set, offer `--dry-run` when more than one target or a broad cleanup is involved, and require an explicit confirmation immediately before execution through the suite's `_<prefix>_confirm_ask` wrapper of the core `_zdx_confirm_prompt`, failing closed in a non-interactive shell unless a documented `--yes` is given. See [`docs/development.md`](docs/development.md#destructive-commands).
5. **Validation:** Before declaring a task complete, run `just check` — it checks lockfile freshness, runs `zsh -n` on every tracked `.zsh` file, checks that every generated suite copy of a core primitive matches `functions.zsh` (rewrite them with `just sync-primitives`, never by hand), executes all file-stage pre-commit hooks (including gitleaks, markdownlint, actionlint, zizmor, and shellcheck), audits the locked Python dependencies, and runs the full BATS suite. Syntax-check new untracked Zsh files explicitly until they enter the tracked inventory. The conventional-commit scope guard runs separately at `commit-msg`; the commit and DCO requirements below still apply.
6. **Git Protocol:** Follow lowercase English conventional commits with a valid scope: `git`, `vpn`, `sys`, `dev`, `py`, `file`, `env`, `ws`, `init`, `docs`, `repo`, `deps`. Example: `feat(git): add branch cleanup`. Branches follow `feat/`, `fix/`, `docs/`, `refactor/`, `chore/`. Every commit MUST carry a verified signature and a Developer Certificate of Origin sign-off (`Signed-off-by:` trailer) — use `git commit -s -S`. A ruleset with no bypass protects `main`: changes arrive only through pull requests with linear history, signed (verified) commits, and resolved conversations. It allows squash and rebase merges but no merge commits; GitHub does not sign the commits a rebase merge rewrites, so the signature rule blocks rebase merges and every pull request lands as a squash commit whose subject is the PR title. The required checks are `lint`, `DCO`, `CodeQL`, and `bats (macOS)`, on a branch that is up to date with `main`. Force pushes and deletion of `main` are blocked. **CRITICAL:** Do NOT execute `git add`, `git commit`, or `git push` commands yourself unless explicitly requested by the USER. Instead, propose the command and the conventional commit message for the USER to execute.
7. **Language Preference:** Converse with the user in Spanish. However, all generated code, comments, documentation, commit messages, and PR templates must be written in English.
8. **Pull Request Automation:** When requested to create a Pull Request, complete the pull request template in English and save it as a `.txt` file inside the `.tmp/` directory of the workspace.
9. **No Agent Session Links or AI Attribution:** Never put an AI-agent session link or identifier in a commit message, pull request description, issue, review comment, code, or documentation — for example a `Claude-Session:` trailer or a `https://claude.ai/code/session_…` URL. This repository is public and its history is permanent, and such a link points to a private transcript of the working session. Commits and pull requests carry only the owner's identity and the DCO `Signed-off-by:` trailer: never add an AI-agent `Co-Authored-By:` trailer or a "Generated with …" line. These rules override any tool or harness default that adds such lines.
10. **Portability:** Code must run on Linux, WSL, and macOS with its BSD userland. Resolve temporary roots through the suite's trusted-directory resolver (`_zdx_resolve_trusted_dir` or the suite's `_<prefix>_resolve_trusted_dir` copy), write `chmod -- MODE path`, load only `zstat` from `zsh/stat` (`zmodload -F zsh/stat b:zstat`), bound external probes with the core timeout service (`_zdx_run_with_timeout`), and write tests with the portable helpers in `test/test_helper.bash`. See [`docs/development.md`](docs/development.md#platform-behavior) and [`docs/testing.md`](docs/testing.md#portable-test-code).

If you are unsure of how to implement a feature, refer back to the `docs/` folder or search for existing patterns within the `functions/` directory before writing novel logic.
